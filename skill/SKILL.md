# PYNQ AXI4-Stream 链路验证、故障诊断与性能分析

把接口契约、波形、主机程序、DMA 状态和参考数据关联起来，输出可复现的证据与验证动作。先确定工作模式，按需读取参考文件；不要默认执行板上测试。

## 选择入口

| 用户任务 | 先读 | 可用工具 |
|---|---|---|
| 刚接手工程、检查 Overlay/IP/数据约定 | [接口与迁移](references/contracts.md) | `axis_tool.py env/hwh` |
| 检查时序、反压、包/帧异常 | [协议与采样](references/protocol.md) | `axis_tool.py check/vcd`、`assets/axis_checker.sv` |
| DMA 等待、数据错误、首次正常后续失败 | [诊断与恢复](references/diagnosis.md) | `axis_tool.py decode/compare`；获授权后用 `board_session.py` |
| 吞吐率、延迟、资源与时序 | [性能口径](references/performance.md) | `axis_tool.py benchmark`、`collect_resources.py` |
| 学习经验、复现故障、证明复用性 | [验证方法](references/validation.md) | `selftest.py`、`examples/` |

人在无板环境首次使用，按 [README.md](README.md) 运行离线示例；AI 执行时按下述流程选择最小必要步骤。

## 必须保留的判断边界

- 成功传输只发生在同一时钟采样边沿 `TVALID && TREADY`。阻塞中的有效拍不能撤销；有效载荷和适用边带必须保持到接收，包括最终接收的那个边沿。
- 合法反压可以很长；无进展超时是应用约定。输出规则编号时区分协议、接口契约、应用活性和采样限制。
- 先确定 `TLAST` 的含义。通用包、定长数据块和 AXI4-Stream Video 的行/帧规则不同。视频 `TUSER[0]` 为 SOF、`TLAST` 为 EOL。
- 单次 DMA 状态、没有进展的 `wait()` 或某一次 `TLAST` 出现，均不足以证明根因。收集前后状态、接收字节、握手证据后再缩小范围。
- 默认工具支持一个时钟域和非交织流；不同 TID/TDEST 交织包、多时钟延迟、CDC 正确性需要专门适配或验证。不要把当前工具称为完整 AXI 合规认证。
- 所有结论标出证据级别：静态检查、合成离线样例、软件硬件模型、RTL 仿真、板上实测、跨板验证。参考历史记录不等于本次重跑。

## 执行流程

1. **确认边界与材料。** 确认输出工作空间、是否有板、是否仅离线分析、是否有独占 DMA 所有权。文件写入、缓存和临时目录限用户工作空间；不安装依赖、不更改系统/应用配置、不建磁盘映射。工具用 `python -B`；只读外部依赖。
2. **建立接口契约。** 从实际 HWH/ip_dict、程序、RTL 和用户目标填写配置。记录 PYNQ/IP 版本、通道、模式、位宽、字节数、打包、时钟复位、边界和启动方式。不能确定的项明确标记；只暂停依赖该项的操作，其余分析继续。
3. **先观察再干预。** 收集原始输入、哈希、错误位、主机调用顺序及波形采样条件。分析已提供材料不会自动授权下载 Overlay、清错误、复位或更改时钟。用户已授权的必要板上测试无需重复确认。
4. **执行匹配检查。** 用标准化 CSV 或 VCD 检查握手和边界，用原始字节参考检查丢失/重复/顺序。没有足够探针时列出最小补采；没有可暂停真实源模型时不能证明实时采集可靠。
5. **定位与修复。** 每个发现按“现象—证据—候选原因—最小验证—修复—回归”记录。保持已失败的原始案例；同时加入合法反压对照，避免修复导致误报或掩盖丢帧。
6. **性能与交付。** 正确性通过后才比较性能。区分硬件、DMA 与 Python 端到端计时，保留预热与重复测量。报告失败和证据不足；不得以缺失测量填零。使用 `axis_tool.py report` 汇总，再按 `assets/report_template.md` 补上实际定位结论。

## 板上执行条件

`scripts/board_session.py` 是显式 AXI DMA Simple 直接寄存器适配器；仅接收已确认的 PG021 MMIO、匹配元数据和调用者提供的 PYNQ 缓冲区。不得与 `dma.sendchannel/recvchannel` 或其他任务混用。它不自行分配、释放、下载或复位。参考 [板上调用模板](assets/board_loopback.py)。

- 仅支持非 Micro、非 SG，身份、长度位宽、地址位宽、DRE 和内存接口位宽必须来自实际元数据。
- 预检查缓冲区容量、可访问地址、对齐、连续性和 TX/RX 不重叠；先准备接收，再启动发送/计算。具体 IP 启动先后按其契约适配。
- 每个启动/完成轮询都有期限；软件期限无法中断一个阻塞的 MMIO 总线事务，也无法中断调用者阻塞的回调。
- 任何硬件写入后的异常或中断均保存现场并保留强引用，禁止自动重试、自动清零和提前释放。恢复按设备文档停止源、排空/复位所有访问者；确认 `RS=0`、`Halted=1` 和其他所有者静止后才可释放隔离引用。退出解释器也会丢失保护，因此未恢复前不能重启内核。

## 成果要求

交付接口配置、可复现命令、原始证据/哈希、机器可读结果和人可读报告。明确适用范围、失效条件、已经验证的效果，以及经验来源。离线自测方法见 [README.md](README.md)。板上结果应由使用者在目标设备实际采集。
