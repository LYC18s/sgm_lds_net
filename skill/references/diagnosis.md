# 故障定位与恢复手册

## 统一取证顺序

保存程序调用与异常、配套构建哈希、DMA 前后状态、超时期限、实际传输长度、缓冲区地址/类型/容量/一致性、波形采样方式。先保留现场再考虑清错/复位；采集动作本身若会读清或写寄存器，应在记录中注明。

本包 `decode` 只处理 `ip_type=axi_dma`；支持 MM2S_DMASR 与 S2MM_DMASR。`Idle/Halted/IOC_Irq` 描述状态，不是完整的数据正确性证明。错误位按 PG021 解码，具体错误条件须对照所用版本、方向和模式。

## 常见现象与最小验证

| 现象 | 候选原因 | 最小下一步 | 修复后验证 |
|---|---|---|---|
| 等待不结束 | 接收没准备、IP 未启动、输入没到、持续反压、边界缺失、DMA 错误 | 对比两方向状态与握手；确认有效字节数；查末拍是否真的被接受 | 多包完成、正常反压、超时注入 |
| TREADY 长期为 0 | 下游未启动、接收容量/FIFO、复位、时钟、DDR 路径或允许的流控 | 查看下一接口与 FIFO 计数；确认反压是否能解除 | 长反压恢复后字节参考一致 |
| TVALID 长期为 0 | 无输入、计算延迟、启动控制、复位，或错误的 ready 依赖 | 检查上游输入与 IP 控制；受控 ready=0 激励，结合 RTL | 三种握手先后、连续输入 |
| TLAST 出现仍卡住 | TLAST 未握手、输出容量/长度问题、其他方向未完成 | 定位 TLAST&&TVALID&&TREADY；读取实际字节和两方向错误位 | 单拍、短包、尾部部分字节 |
| 反压后丢失/重复 | 计数按 valid 推进、待接收数据被覆盖、FIFO 错误 | 查首次不一致附近握手，比较接受拍序列 | 原种子与更多合法反压种子 |
| 数据像旧帧/随机偏移 | 缓存不同步、布局/字节序、缓冲区复用或异步读写竞争 | 设备地址与所有权记录；固定图案；参考字节偏移 | 多帧序号、哨兵、重复启动 |
| 首次成功后失败 | 状态未清、IP 未重新启动、缓冲区生命周期、重复所有者 | 检查第 1/2 包状态与调用；确认唯一所有者 | 连续 N 包与停止/重启 |
| RGB 正常而计算支路无完整帧 | 非暂停真实源压垮慢分支，合法丢弃策略触发 | 不等待下游的源模型、分支吞吐及丢帧计数 | 实际速率模型、完整帧参考 |
| DMADecErr | 地址映射/设备地址/位宽错误 | 对照硬件地址图和 buffer.device_address | 合法地址与边界长度 |
| DMASlvErr | 内存侧 slave 返回错误 | 取 AXI 响应、连接、时钟复位与访问限制 | 错误注入与正常内存响应 |
| DMAIntErr | 按版本/模式可能涉及长度、接收容量或内存写错误 | 对照 PG021 与实际包长，不能只归因 TLAST | 正常长度与超限对照 |

输入输出数值不同也可能来自量化舍入、饱和、符号扩展或算法定义。先确认数据打包与黄金模型一致，再归因传输。

## 自动化动作边界

只读分析：`axis_tool.py env/hwh/check/decode/compare/benchmark`。`board_session.snapshot` 仍是硬件读，必须已经确认 MMIO 的身份和寄存器副作用。

显式执行：`run_simple` 修改 DMA 控制、地址、长度，并清除旧 IOC；所以必须独占整个实例，不与已有 PYNQ DMA 对象、其他线程/进程混用。它不会清错误、复位、分配或释放。

流程是预检查 → TX/RX 缓存准备 → 清旧完成标志 → 启动并有界等待退出 Halted → 接收地址与长度 → 发送地址与长度 → 非阻塞 IP 启动钩子 → 有界等待完成 → 检查错误与新 IOC/Idle → 接收同步 → 比较实际长度与数据。

对于需要 IP 先启动才能接收、输入输出不同比例、外部自由运行源的场景，按端点契约审查/调整钩子及启动流程。当前模板不能保证任意 IP 原样可用。

## 超时与缓冲区恢复

1. 立即停止后续提交；保留原始异常和状态，不自动反复复位。
2. `QUARANTINE` 持有 MMIO 和所有缓冲区的强引用；不要在 finally、with 或异常路径中 free/close 这些缓冲区。不能重启 Notebook 内核来“清理”仍活跃的总线主设备。
3. 按硬件文档停止源及其他访问者；排空尚未完成的事务。必要复位仅在相应授权和已明确影响范围下进行，复位动作也应有超时。
4. 确认所有所有者静止，DMA `RS=0` 且 `Halted=1`，再调用 `release_quarantine_after_recovery(..., upstream_quiescent=True)`。该参数是调用者已完成核验的声明，不是自动检测。
5. 返回的 entry 仍持有缓冲区；在确认其他设备不再访问后，由分配者释放。恢复前后现场和复测结果一起记录。

硬件访问本身挂死不能靠普通 Python 线程或循环期限中断。不要启动无法终止的后台 `wait()` 线程作为超时方案。
